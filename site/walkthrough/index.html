How the native calls were made

An isolated Chrome testing profile exposed the actual browser API. We selected the returned tool objects and passed object arguments, as supported by Chrome 155 and later. No replacement document.modelContext was installed.

const tools = await document.modelContext.getTools();
const state = await document.modelContext.executeTool(
  tools.find(tool => tool.name === 'uk_security_get_state'), {}
);
const answer = await document.modelContext.executeTool(
  tools.find(tool => tool.name === 'uk_security_answer'),
  { snapshot_id: state.snapshot_id,
    question: 'What should govern an agent that can use government APIs?' }
);

See the 27 October WebMCP draft and Chrome imperative API guidance. Browser testing does not establish that every AI host exposes these tools.

QUESTION 2 · uk_security_answer

Does an API token authorise the agent's whole task?

Separate an API permission from approval for a whole task.

The source quotation supports resource-level access control and checking the required scope on each request. The whole-task conclusion is explicitly our analysis. A valid token is evidence about a request; the organisation still needs to decide the permitted objective, resources and disclosures.

Direction for future work: Map each proposed action to both its API scope and the task decision that authorises it.

QUESTION 4 · uk_security_answer

How can we express governance as code?

Turn selected agreed decisions into inspectable checks.

The answer distinguishes local interpretation from the synthetic policy exercise. Versioned rules can check selected conditions, but a passing code result cannot establish every legal, ethical or organisational obligation.

Direction for future work: Agree which rules are suitable for automation and retain their authority, version, input context and decision evidence.

Build evidence around claims and adverse cases.

QUESTION 7 · uk_security_answer

Does WebMCP enforce our governance policy?

Treat the tool interface as one implementation boundary.

The page exposes bounded read-only tools. Its annotations describe those tools; task authority, consent and input limits are implemented separately. This capture proves native execution in the tested browser. It does not prove an AI host has a callable bridge.

Direction for future work: Inspect the actual inventory, test the implementation boundaries and verify the intended AI host separately.
